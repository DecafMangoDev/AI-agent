# Проектные решения для уровней 9 и 10

## Уровень 9: задачи как проверяемый граф

План хранится в SQLite в поле `runs.plan_json`, а после approve его шаги становятся строками таблицы `tasks`. Каждая задача имеет `task_id`, описание, список зависимостей и состояние. Поле `tools` в плане остаётся рекомендацией модели: runtime не требует выполнить весь перечисленный список, если фактический результат задачи достигнут другим допустимым вызовом.

Runtime выбирает только первую задачу, у которой все зависимости имеют статус `done`. После успешного tool call задача переходит в `awaiting_review`, а CLI показывает сокращённые имя инструмента, аргументы и результат из журнала `calls`, затем спрашивает пользователя, удовлетворён ли он. Подтверждение переводит задачу в `done` и сохраняет `completed_call_id` и решение пользователя. Отказ возвращает задачу в `running`, сохраняет комментарий пользователя и передаёт его модели для следующей попытки. Текстовый ответ модели сам по себе состояние задачи не меняет.

Результат tool call не копируется в `tasks`: он уже хранится в `calls.result_json` и сообщениях истории. Задача хранит ссылку на подтверждающий вызов и решение пользователя. После `/resume` завершённая задача не запускается повторно. Команда `/tasks` показывает этот граф как чеклист.

## Уровень 10: журнал файлов и безопасный rollback

Перед записью, удалением и allowlisted Bash runtime строит снимок дерева UTF-8 файлов. Снимки и изменения хранятся в SQLite. Для каждого пути остаются исходное и итоговое содержимое, SHA-256 и unified diff; это одинаково покрывает изменение, создание и удаление файла. Перед следующим побочным действием текущий снимок сравнивается с последним. Любая внешняя правка останавливает операцию до явного решения пользователя.

Rollback проверяет итоговые хеши по журналу и восстанавливает только файлы данного `run_id`. Если хотя бы один хеш изменён извне, не перезаписывается ни один файл. Неопределённый вызов после сбоя сначала переводится в `unknown`, а затем разрешается `/resolve <id> retry|fail|abort`.

## Что видно пользователю

CLI печатает короткие события в stderr: запуск run, запрос к модели, имя инструмента, результат, завершение задачи и восстановление. Длинный ответ остаётся в stdout. Такой поток не требует угадывать, завис ли терминал, и не связывает бизнес-логику с выводом.
