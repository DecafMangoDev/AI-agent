# Проектные решения для уровней 9 и 10

## Уровень 9: задачи как проверяемый граф

План хранится в SQLite в поле `runs.plan_json`, а после approve его шаги становятся строками таблицы `tasks`. Каждая задача имеет `task_id`, описание, список зависимостей, состояние и `evidence_json`. Runtime выбирает только первую задачу, у которой все зависимости имеют статус `done`; текстовый ответ модели не меняет состояние задачи. Состояние меняется только после успешного tool call, который записывается в evidence. Поэтому после `/resume` завершённая задача не запускается повторно. Команда `/tasks` показывает этот граф как чеклист.

## Уровень 10: журнал файлов и безопасный rollback

Перед записью, удалением и allowlisted Bash runtime строит снимок дерева UTF-8 файлов. Снимки и изменения хранятся в SQLite. Для каждого пути остаются исходное и итоговое содержимое, SHA-256 и unified diff; это одинаково покрывает изменение, создание и удаление файла. Перед следующим побочным действием текущий снимок сравнивается с последним. Любая внешняя правка останавливает операцию до явного решения пользователя.

Rollback проверяет итоговые хеши по журналу и восстанавливает только файлы данного `run_id`. Если хотя бы один хеш изменён извне, не перезаписывается ни один файл. Неопределённый вызов после сбоя сначала переводится в `unknown`, а затем разрешается `/resolve <id> retry|fail|abort`.

## Что видно пользователю

CLI печатает короткие события в stderr: запуск run, запрос к модели, имя инструмента, результат, завершение задачи и восстановление. Длинный ответ остаётся в stdout. Такой поток не требует угадывать, завис ли терминал, и не связывает бизнес-логику с выводом.
